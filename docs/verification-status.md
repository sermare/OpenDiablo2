# Verification status of the oracle work

One row per area. The columns are what is implemented (and where), what was **verified against the
1.14b `Game.exe`** (only addresses and observations are recorded here, no decompiled code), what is
**unverified or assumed**, the known engine gaps, and the test that pins it.

Status as of `integration-s9-rehearsal` (96a9c5d4). Sources: the `VERIFIED` / `UNVERIFIED` comments in the
packages, their tests, commit messages, and the reverse-engineering notes `verify-monster-hero.md`,
`verify-boss-flag.md`, `monster-scaling-complete.md`, `monster-ai-remaining.md`, `verify-monster-ai.md`,
`verify-affix-objects-path.md`, `verify-skilldesc.md`, `skilldesc-damage.md`, `verify-hit-resolution.md`,
`verify-resist.md`, `verify-undead-helper.md`, `verify-states.md`, `verify-inventory.md`,
`verify-item-rules.md`, `verify-vendor.md`, `verify-level-graph.md`, `verify-skill-tree.md`,
`verify-xp-gain.md`, `verify-quest-rewards.md`, `anim-speed-oracle.md` (copies of the first two are in
this directory). Where a rule was verified in the exe but the fix is only on a fork branch that this tree
does not contain, the cell says so and names the branch (see [Verified in the exe but not in this
tree](#verified-in-the-exe-but-not-in-this-tree)). Addresses are virtual addresses in `Game.exe` 1.14b. This page covers the
oracle audits only; for feature-level status see [STATUS_MATRIX.md](STATUS_MATRIX.md) and, for how the
evidence is produced, [TESTING.md](TESTING.md). Where this page and a package comment disagree, the
package comment is the detail and the code is the truth.

"Pinned by" lists tests. Tests marked (env) skip unless the environment variable named in
[How to run the oracle tests](#how-to-run-the-oracle-tests) is set, so a green CI run does not exercise them.

## Notes that changed the code (so older notes may read stale)

Corrections, newest knowledge first. Where two notes disagree, the later one is exe-verified.

* **Boss flag.** `verify-boss-flag.md` corrects the earlier guess in `monster-scaling-complete.md`
  (which said bit 6 is probably primeevil and boss bit 5): mask 0x40 (0x006cf268) on the monstats flag
  dword is **boss** (bit 6), primeevil is bit 7. The level gate uses boss and noRatio.
* **Sanctuary tests undead, not boss.** `verify-resist.md` item 5 said the state 0x2f rule keys on the boss
  flags; `verify-undead-helper.md` (exe-verified) shows helper 0x0063f9e0 tests lUndead / hUndead
  (monstats byte +0xd masks 0x08 / 0x10). Fixed in `88a97565`.
* **Durability loss.** `itemgen.md` had armor and weapon reversed. Verified at 0x00557d90: armor 10 percent,
  weapon 4 percent (throwables 10 percent in an expansion game, none in classic). The code was right.
* **Item socket borders.** MaxSock switches at item level 25 and 40 inclusive (0x0062bd70); the earlier
  Go border `ilvl < 40` was wrong.
* **Hit resolution order.** Flat reduction, then percent resist, then absorb, per type, with the pvp / merc
  scale applied before the type loop; all queued at 0x0057bc00 -> 0x00579ef0, not at resolve time. A
  failed evade ends the avoid chain and sets no result bit. 0x0057bcb0 is the Weapon Block passive
  (stat 0x15c), not the monster stat-20 block chance. Ghidra's name `ITEM_PotionApplyTimedRecovery` for
  0x005bda80 is wrong (it is open wounds).
* **Summoner wake-up.** `verify-monster-ai.md` section 8 said a counter below 20; `monster-ai-remaining.md`
  corrects it to the tick distance below 20, as the first note said. The wounded teleport, the threat
  re-target, the idle wander and the SandRaider overlay were ported afterwards (`882f621c`), as
  host-supplied hooks that are off in the engine; `d2monster/doc.go` may still list some of them as
  missing.
* **ResolveLevel.** The note "d2monster.ResolveLevel does not gate on expansion" is closed: it now
  delegates to `d2monstats.Class.ResolveLevel`, which requires the expansion flag.
* **skilldesc kind 13.** `skilldesc-damage.md` corrects `verify-skilldesc.md`: kind 13 (0x004eb140) is the
  summon life line, not a descdam dispatcher; descdam is a separate header-damage path that is not
  modelled. The skill tooltip is one text box, not two.
* **Vendor.** `verify-vendor.md` corrects the earlier vendor notes: the Min / MagicMin columns are read, the
  magic pass is gated by reqlevel, the item level cap is indexed by the town act and applies on Normal
  only, Cain's identify accepts classes 244..246, 265 and 520. `d2vendor/doc.go` in this tree still
  carries the old statements.
* **Skill tree.** The level gate applies to every point (reqlevel + points already spent), and the
  effective skill level is clamped to the Experience.txt MaxLvl (99), not to the skills.txt maxlvl.
  The comments in `d2common/d2skill/levels.go` and `d2core/d2hero/skilltree_rules_real_test.go` in this
  tree still say both are unknown.
* **Level graph.** Levels.txt QuestFlag is a record slot checked only by the town portal object use; the
  warp tiles use their own node-based gate list (73, 100, 118, 128, 132). `d2level/gates.go` models all
  gates as QuestFlag slots (its comment: "inference ... UNVERIFIED").
* **Quest rewards.** Golden Bird's claim spawns the Potion of Life (the +20 life is paid on use, stat 7 +=
  0x1400), Prison of Ice gives the Scroll of Resistance (paid on read, +10 per difficulty record, stats
  39 / 41 / 43 / 45, re-applied on every join), Radament gives no reward, Fallen Angel gives 2 skill
  points, Lam Esen 5 stat points. A saved pending reward is inert for kills and area events but its claim
  line is still offered (`quests-2.md` is right; `quests.md` "inert" applies only to unforced events).
* **Ethereal.** Ethereal items get +50 percent base damage and defense through `FUN_00660a40`, (v*3)/2
  truncating (`d5ada317`); `verify-item-rules.md` had called it unverified. Vendor items can be socketed
  but are never ethereal.
* **Animation speed.** With 0 FHR the hit recovery animation runs at half the AnimData speed; the community
  frame lists differ by one frame. The d2herostats rows for Necromancer FHR, Barbarian FHR, Sorceress FBR,
  Necromancer FBR and Druid FBR were wrong and were rederived (`911b77ce`).
* **Open wounds / crushing blow.** Stat 135 is item event function 15 (0x005bda80), stat 136 is function 16
  (0x005bdbf0); both run after the base damage.
* **Attack rating +0x16.** The monster data word +0x16 read by 0x0059dd60 is a per-spawn type mask, not a
  monstats column (`fork/feat/verify-monster-flag16`, `cba3d7e1`).

## How to run the oracle tests

Nothing from the game is committed. Point the tests at your own extracted data; every test that needs
data skips (does not fail) when its variable is unset, so `go test ./...` is always green on a bare
checkout and proves only the synthetic tests. Run from the repository root:

```sh
D2_TABLES=$HOME/git/d2-tables \
D2S_SAMPLE_BODY=/path/to/real.d2s D2S_SAMPLE_BODY_JSON=/path/to/real.d2s.json \
D2_TBL_DIR=/path/to/tbl \
go test ./d2common/... ./d2core/... ./d2game/... 
```

| Variable | What it points at | What is skipped when it is unset |
|---|---|---|
| `D2_TABLES` | A folder of tables extracted from your own MPQs (`monstats`, `monlvl`, `skills`, `Experience`, `Levels`, `itemstatcost.bin`, `armor`, `weapons`, `misc`, `ItemTypes`, and so on; each test reads the file names it needs) | Real-table tests of `d2monstats`, `d2monster` (`TestRealMonstats`, `TestRealSpawnData`), `d2summon`, `d2calc`, `d2skill` (`TestReal*`), `d2drop` (`TestReal*`), `d2object`, `d2path` (`TestMonstatsVelocities`), `d2statlist`, `d2herostats`, `d2equip`, `d2hireling`, `d2level`, `d2automap`, `d2quest` speech, `d2drlg` and its sub-packages, `d2sfx`, `d2mapgen`, `d2records` skill pipeline, `d2gamescreen` `TestLevel94Oracle`, and the table-dependent `d2s` item tests. `d2s` robustness tests and `d2hero` `TestExportCorruptOriginal` default this to `~/git/d2-tables` when unset |
| `D2S_SAMPLE_BODY` | A real `.d2s` with a body (quests, waypoints, stats, skills, items), for example a level-94 save | The real-save tests in `d2s` (body, writer, quests, items), `d2hero` (containers, export, totals) and the robustness tests (which default to `~/git/d2s-test/NokkaSorc.d2s`); also `d2herostats` derivation on a save when `D2S_SAVE_JSON` is unset (it then reads `D2S_SAMPLE_BODY` + `.json`) |
| `D2S_SAMPLE_BODY_JSON` | The expected parse of that save from an independent parser (nokka `d2s` JSON format) | The `d2s` body equality test (needs both variables). `D2S_SAMPLE_JSON` does the same for the item test; `D2S_SAVE_JSON` for `d2herostats` |
| `D2_TBL_DIR` | A folder laid out `<LANG>/string.tbl`, `<LANG>/expansionstring.tbl`, `<LANG>/patchstring.tbl` for `ENG`, `DEU`, `FRA`, `POL`, `KOR`, built by you from your MPQs | The four `TestReal*` tests in `d2tbl/localisation_test.go`; a missing language or file inside the folder is skipped per table |
| `OD2_PLAYERS` | Not a test input: an engine override (0..8, 0 or invalid means none) for the monster player count used by player-count scaling, read in `d2game/d2gamescreen/game_monsters.go` and parsed by `d2monsters.ForcedPlayersFromEnv` | Nothing is skipped. Unset, the count comes from the connected players. The parsing is pinned by `TestForcedPlayersFromEnv` and the effect on later spawns by `TestPlayersOnlyAffectLaterSpawns`, both without data |

Other gates not covered by the four variables: `D2_DS1_ROOT`, `D2_DS1`, `D2S_SAMPLE`, `D2S_SAMPLE_NEW`,
`D2_INSTALL`, `D2_PL2`, `D2_DEFAULT_KEY`, `D2_DIFFICULTYLEVELS` (see [TESTING.md](TESTING.md)). Scenarios
in `scripts/verify.d` need a GUI session and run only through `scripts/verify.sh`; they show the pieces
work together, not fidelity to the original.
