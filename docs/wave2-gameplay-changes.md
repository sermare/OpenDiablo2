# Wave 2: gameplay-behaviour changes for owner review

Scope: every commit on the wave-2 `fork/feat/*` branches (versus `fork/integration`; `fork/integration-s2` does not exist on the fork) that changes what the game does. Pure tests, oracles, fuzzers, race fixes and docs are listed at the end only.
Sources: commit messages, code comments and tests of those commits, and `~/git/d2-re-notes/*.md`. Nothing here was run or re-verified for this document.

Refreshed against `integration-s9-rehearsal` (96a9c5d4): rows whose basis was later verified in the exe, or whose statement was corrected, are updated in place and marked "(Refreshed)". New gameplay changes since the first version are in [Added since the first version](#added-since-the-first-version). Verified rules per area are in [verification-status.md](verification-status.md); several verifications live on fork branches that this tree does not contain (listed there).

Notes on attribution: several commits are reachable from more than one branch (for example `feat/wire-states` carries the earlier oracle commits). Each commit is listed once, under the branch that `git log --source` reports first. "Revert" means `git revert <commit>`; no change below has a runtime flag unless stated.

### Conflict notes for `pass2-s2`

- `d2common/d2skill/class.go` `strike()`: kept the attack-rating operand adjustment AND the mastery to-hit percent.
- `d2common/d2combat/reduce.go` (from merc-gear-combat) duplicated `ReduceComponent` of `hit.go`: removed; the merc code and tests use the single verified function. Two semantics changed: the ignore flag now skips a positive resist and leaves damage unchanged (the merc copy zeroed it); mercs get no absorb.
- `d2core/d2hero/merc_gear.go`: removed a duplicate `clampInt` that `d2s_item_export.go` already defines.
- `d2common/d2missile/damage.go`: kept the integrator's `missile-damage-oracle` `Roll` and added the descriptor crit doubling (flag 0x2 doubles physical damage after the percent bonus and sets the critical result bit). The oracle's `d2combat.BuildMissileDamage` already does the same for missile stat 0x8d, so the two agree.
- `d2core/d2monsters/combat.go` and `d2core/d2skills/units.go`: both sides are additions (`heroAutoHit`/`heroPhysicalDamage`/`noteBlockAnim` and `Director.UnitID`; `AdjustAROperands` and `EnemiesWithin`); both kept.

The scenario itself was never run by its author.
- **Party XP check (`kill=42103 host=1440 joiner=1440`).** `feat/wire-party-xp` makes the server split the kill and then scale EACH share by that member's own level against the monster's level (verify-xp-gain.md level scaling: a hero much higher than the monster gets a small fraction, and a level 99 hero gets 0). So host + joiner no longer add up to the kill XP. If the check asserts the sum equals the kill XP, the check is stale, not the split.
