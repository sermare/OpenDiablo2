# verify-missiles: Game.exe 1.14b missile hit/collision rules settled (addresses and observations only)

Method: Ghidra decompile and raw bytes, read-only. Functions at 0x5a8100, 0x5a8680 and 0x5a6130..0x5a62b0 are not defined as functions in the project, so they were read via disassemble_bytes (decoded by hand). "verified" = read in code or bytes; "unverified" says what is missing.

## (1) ProcessHitOrExpire 0x5aba10 and hit function returns
- verified: A (result bits: 1 destroy, 2 apply damage fn, 4 keep) starts at 2 (0 if rec flag Explosion), |1 for CollideKill. B (3) bit 1 = may destroy, bit 2 = run hit function. The hit function return value REPLACES A (not ORed). A&4 returns 1 at once (missile lives, no damage). Damage fn runs only with a target and A&2. Destroy if (A&1 or expire) and B&1.
- Hit function runs also with a null target on expiry / path end / wall (expire arg = 1): AlwaysExplode only matters for a to-hit miss (and the never-used (0,0) call).
- Return values: hit 1 (0x5a7500) returns 1 -> kill, NO direct damage; hit 2 (0x5a7810) returns 3; hit 4 (0x5ae370) returns 3 (loop exit value 1, +2); hit 14 (0x5a8680) returns a skill record pointer left in the return register (no mov of a constant on the success path; returns 3 only if the 0x569830 wrapper returns 0, which it never does) - bits 0..2 clear in practice, treated as 0; since expiry destroys anyway the effect is nil.
- Hit 1: radius = rec sHitPar1 (+0x4c) when > 0 else skill calc at skill+0x138 (min 1); one damage struct (0x5a6690) rolled once. Hit 14: same but calc at skill+0x64; then HitSubMissile1 (+0x24, >= 0) is spawned at 18 offsets (tables 0x6e3a00 x, 0x6e3a48 y, int each: x = 2,-2,0,0,-3,0,3,-1,1,-1,2,-4,-3,-1,0,1,3,4; y = -2,-2,2,5,3,3,3,2,1,-1,-1,-2,-2,-3,-4,-3,-3,-2) stepping sHitPar2 entries (min 1), via 0x5a8550, createStruct flag 1, lifetime override flag 0x8000 with skill+0x150 + (lvl-1)*skill+0x154 (0x4c9220) when > 0.
- Hit 10 (0x5a8100, Guided Arrow), missile data field +0x28 = mode (set 1 with a target, 2 without by SRVDO_010 0x5da2f0, which uses create flags 0x20 / 0x420): target null and mode&4 -> 1; mode&1: null target or the path target -> 3, any other unit -> 4; mode&2 == 0 -> 3; life <= 0 -> retarget 0x5a8060 (returns 1 if mode&4, else searches around the missile with rec Param2 (+0x3c) as radius (unverified: argument mapping of 0x569a80/0x569510 is muddy) and calls 0x5a7f10: life = (lvl-1)*LevRange + Range, mode 5 (target) or 6 (new ground leg = old owner-to-aim offset), returns 0 -> hit returns 4); life > 0 -> mode&4 ? 3 : 4. Town: returns 1.
- Area radius unit (item 5): 0x569510 compares MATH_DistanceSquared2D(center, unit) <= radius^2 with center = UNIT_GetPosX/Y of the missile and units' PATH_GetXPos/YPos = path+2/+6 = integer SUBTILE coordinates. So radius is in subtiles, euclidean. Fireball sHitPar1 = 4.

## (2) Pierce
- 0x59d4e0 (called from CreateServerMissile): only for a missile with rec flag4 bit 2 (Pierce) whose owner is player or monster: chance = stat 0xa6 (skill_pierce) + full stat 0x9c (item_pierce); if nonzero, up to 4 times: percent roll (LCG 0x6ac690c5 on the shared seed, % 100) < chance -> charge++, first failure stops; stored as missile stat 0x148 (pierce_idx). So 0..4 charges, geometric.
- 0x5ab550 (called in ProcessHitOrExpire for a target, only if rec Pierce flag and owner has stat 0xa6 or 0x9c): if missile stat 0x148 != 0 then B = 2 and the stat is decremented; else B = 3. Done before the CollideKill / ToHit steps, so a charge is spent even if the to-hit roll then misses.

## (3) CollideType
- 0x5ab510 (target filter inside ProcessHitOrExpire, arg = CollideType): 0 -> reject, 1 -> only unit type 0 (player), 2 -> only type 1 (monster), default accept (3..8). Null unit counts as type 6.
- Cell masks / predicates, table 0x739948 stride 8: 0 {-,0}, 1 {0x5a6210,0x84}, 2 {0x5a61d0,0x104}, 3 {0x5a6270,0x184}, 4 {-,0}, 5 {0x5a61d0,0x104}, 6 {-,0x4}, 7 {0x5a62b0,0x40}, 8 {0x5a6270,0x185}.
- Common predicate 0x5a6160: target flags (unit+0xc4) bits 3 and 2 set; if NextHit then target has no state 0x56; last-hit dedupe 0x64b700 (rec flag LastCollide, compares missile data +0x18/+0x1c); owner present -> must be enemy (0x552270) or rec CollideFriend (+0x187).
- 0x5a61d0 (types 2, 5): target type == 1 (monster) + common. 0x5a6270 (3, 8): type 0 or 1 + common. 0x5a6210 (type 1): type 0, or type 1 only if 0x625c10 == 2 (monster with state 0x69 whose stat 0xac is 2; unverified meaning) + common. 0x5a62b0 (type 7): target is a MISSILE (type 3) whose rec flag byte & global byte at 0x6cf260 - missile versus missile; walls are not in its mask.
- The collide type is stored at unit+0x10 and indexes the table in SrvDoStandardMove 0x5abd00: type 0 returns 1 before any wall test; type 6 returns 1 after the wall test; if the table function is 0 (types 4, 0) and the cell flags are nonzero the missile is destroyed (return 2, no hit function).
- Wall bits: path+0x54 (cell flags, zeroed each step by 0x651ad0) & 5 (0x1|0x4) at the missile cell -> return 2 immediately, NO hit function / explosion; checked before the Activate test, and recomputed from the grid for a stationary missile (velocity 0). The step routine 0x6515b0 stops at the first blocked cell (stays at the last free cell), records the free cells entered (list +0x1d8, max 10) and sets path flag 8 when at least one cell was entered (this is PATH_TestFlag08, used by SrvDoFunc 2 and 6 to spawn a SubMissile per step into a new subtile). Unverified: 0x6513e0, the per-cell test that applies the mask (so "a wall bit in the type's mask ends the missile through ProcessHitOrExpire(0,1)" and "a wall bit outside it vanishes silently" are inferred from the table bytes plus the two code paths).
- Mask terrain bits per type: 1,2,3,5,6 -> 0x4 only; 8 -> 0x1|0x4; 7 -> none (0x40 = missile bit).

## (4) SrvDoFunc
- 7 (0x5ac2c0): owner missing or in death mode, or missile in town -> return 2 (destroyed). If missile data +0x28 bit 0: target = path target (excluding self); dropped if dead or not an enemy; period = rec Param1 (+0x38, default 5 if < 1); when remaining life % period == 0 and distance to the target 4..24 (UNIT_GetDistanceToUnit; unit assumed subtiles) the path is recomputed to the target (instant re-aim); otherwise straight. Then standard move. guidedarrow row: Param1 5, Param2 15.
- 6 (0x5ac1b0): owner and rec SubMissile1 (+0x18) must exist else return 2; if path flag 8 (entered a new subtile) spawn SubMissile1 (createStruct flag 0x21) at the missile, then standard move. 2 (0x5abf30): same trigger through 0x5a7170 (flags 5 / 0x8005 with rec+0x80 lifetime, level*2-2 as sub-loop). 5 (0x5ac050): flame animation counter (SubStart +0x181). Used by the oracle rows: 1 (plain), 2 (poisonjav), 7 (guidedarrow); 5 for meteorfire.
- NextHit (0x5ab5d0): puts state 0x56 on the TARGET for NextDelay frames (stat list expiring at game frame + NextDelay), so it is shared by all NextHit missiles. Called before the hit function and also on a to-hit miss.
- Create (0x59d5d0) confirmed: Accel -> 0x649ac0(short rec+0x9e), MaxVel -> 0x649a90(byte rec+0x9c << 8); aim equal to start becomes (+1,+1); distance >= 100 in x or y refuses; flag 0x400 lob: life = dist<<16 / (vel<<4).
