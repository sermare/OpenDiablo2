# Mercenary verification pass (Game.exe 1.14b; addresses and observations only)

(Placed in docs/ because agents may only edit inside their worktree; copy to ~/git/d2-re-notes/verify-merc.md.)

1. Max merc level. DAT_009648e8 is the experience.txt table (32 B/level, columns Amazon..Assassin at +0,4,..; row 0 is the "MaxLvl" row = 99 for every class). DATATBL_GetMaxLevelForClass(0) = 99.
   - MERC_AwardExperience 0x57c860: no gain when merc level >= 98 (compares against max-1); its level-up loop stops at 98. The exp stat is stored first; the threshold for level n uses the ExpLvl of the row valid at the STARTING level (row looked up once).
   - MERC_SetLevelStats 0x570690: next-level exp stat 0x1e is 0 from level 98 on.
   - Save loader MERC_LoadFromD2sHeader 0x568730: level scan runs while level+1 <= 99, so a save with enough exp loads at 99; threshold(level+1) uses the ExpLvl of the row of the CURRENT level. Exp stat = max(saved, current).
2. Exp multiplier. Caller 0x57c990 (kill credit): merc found via 0x572cc0 (relation 7); gain = pipeline 0x57c490 with the MERC's level and the merc as recipient; if the merc is not the unit that made the kill, gain = gain*0x56 >> 8 (IMUL/CDQ/SAR at 0x57ca2d); then 0x57c860 adds 2 * gain to the merc exp (register argument EAX). Only when merc level < owner level and < 98. Matches verify-xp-gain.md.
3. Hire gates (HIRE_ProcessHireOffer 0x574f00). Qual-Kehk (0x203): quest record bit 0 of slot 0x24 (36 = Rescue on Mount Arreat) in the record of the game difficulty (game+0x6d). Kashya (0x96): when the gate level < 8, bit 0 of slot 2 (Sisters' Burial Grounds). Helper 0x5746a0: only when the difficulty byte is 0 and vendor-record byte +0x22 < 5, level = min(level, {12,20,28,36,45}[idx]); all caps exceed 8 so Kashya is unaffected. The meaning of +0x22 (act?) is unconfirmed.
4. Boss damage. Percent helper 0x579d70 (damage struct: +4 difficulty row, +8 attacker, +0xc defender): when the attacker is a hireling class (0x63fed0 returns 1 rogue 0x10f, 2 desert 0x152, 3 Iron Wolf 0x167, 4 barbarian 0x230/0x231) and the defender's monstats record has flag 0x40 (byte +0xc, probably the boss column), percent = DifficultyLevels +0x38 (HireableBossDamagePercent; 100 when no row). Hireling vs hireling = 25 (0x19); monster vs player 100 in the normal case, 17 (0x11) otherwise. Used by COMBAT_ApplyResistsToDamageStruct, which scales every damage component by percent/100. Merc resists: stats 0x27/0x29/0x2b/0x2d only (fire, lightning, cold, poison), all max(0, Resist + ResistLvl*d/4); no physical/magic.
5. Save header. Struct base 0xAF: dword0 bit 16 = dead = bit 0 of the byte at 0xB1 (not any non-zero u16). Existence = dword 0xBB (exp) | dword 0xB3 (id) | low u16 0xB7 (name id); the type at 0xB9 is not tested. Name = NameFirst + nameId, wrapped to NameFirst past NameLast. Whether the 'jf' section is read under the same condition was not traced.
6. Follow (MONAI_Think_Hireable 0x5e4240): edge distance > 100 teleports; outer 0x18 (24) and inner 0x10 (16) unless AI param +0x14 is 0x11..0x13 (then inner = value, outer = 2*value, step radius value>>1; default radius 5). MERC_RelocatePetsWithOwner 0x5732b0 walks the pet types (0xe0-byte rows at +0xbe8, flags byte at +4): bit0 -> FUN_00572b90, bit1 -> FUN_00573180 (calls NPCSRV_AddPlayerPet(unit,1) for living pets when MATH_DistanceSquared2D(owner,pet) > 0x640; the old note had the direction reversed), else FUN_00572a70. Which pettype row has which bits is unknown (pettype.txt not extracted: absent from d2data/d2exp mpq).
7. Iron Wolf. MERC_DecideAttack 0x5e3fa0 branches on monstats AIParam1 for the difficulty (short at +0x56+2*diff): non-zero = close branch (edge < 3 and visible: attack, else run at the target); zero = ranged-style branch (edge < 4: 50% step near/away, else attack). Data: 271 = 0, Guard 338 = 1, Iron Wolf 359 = 0 ("not melee"), barbarians = 1. So the Iron Wolf uses the ranged-style branch. Pressure constant 0x62 for 0x152/0x230/0x231 else min(0x5f, ai+0x14 + 0x28 + 2*level).
8. Revive allow-list (0x577a10): 0xfc Asheara, 0x96 Kashya, 0xc6 Greiz, 0x203 Qual-Kehk, 0x16f = 367 = Tyrael (act 4). Needs a type-7 pet record (dead included); cost min(50000, lvl^2/2*15).

Engine: d2hireling MaxLevel 98 / MaxLoadLevel 99 / LevelAfterGain / LevelFromExp, gate.go, d2s dead bit + Mercenary.Exists, merc exp share 86/256, boss damage scaling, Qual-Kehk and Tyrael menu rows. Not changed: merc equipment slot rules (unverified), the relocation limit (pettype flags unknown), 'jf' read condition.
